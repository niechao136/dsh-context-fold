# dsh-context-fold

长会话里最贵的不是历史，而是**已经用完的正文还在每一步重发**。

这个插件在阶段边界把「已经得出结果、后面不再需要全文」的工具输出和思考过程折叠起来：结论留在窗口里，原文落到 spill 文件，随时可以取回。

```
[context-fold] [tool: ops_grep] 12,480 chars folded.
Conclusion: 找到 3 处调用点，都在 src/routes.ts。
Full result: C:\Users\...\dsh-spill\xxx-tool-42.txt
```

原文没有丢，只是不再每一步都付钱重发。

---

## 快速开始

### 1. 安装

在 DSH 的插件市场里搜索 `dsh-context-fold` 安装，或直接写进 profile：

```yaml
# profile 的 cordis.patch.yml
- id: context-fold
  name: dsh-context-fold
```

装好后**重启 DeepSeek Harness**。

### 2. 确认它在工作

打开任意一个对话，在右侧或对话区找到「上下文折叠」标签页。你会看到：

- 折叠了多少处、省了多少 token
- 每一处折叠的结论，展开可以看到完整原文
- 收益是正还是负

### 3. 按需调整

设置 → 插件 → 上下文折叠，有 9 个可调项。改完需要重启生效。

## 你会看到什么

### 对话里的标签页

标签页分两块：

**Token 对比** —— 六个指标卡片

| 指标 | 含义 |
|---|---|
| 当前折叠后 | 窗口实际承载多少 token |
| 若从未折叠 | 不折叠的话会有多少（反事实估算） |
| 每步节省 | 每次请求少发多少 token |
| 总收益 | 每步节省 × 剩余步数 |
| 失效成本 | 折叠会打掉前缀缓存，需要重算一次的费用 |
| 净收益 | 总收益 − 失效成本 |

**净收益为负时会标红**，含义是「折叠得太晚，已经亏了」。这不是 bug，是插件在如实告诉你这次折叠不划算。

**折叠明细** —— 每条记录一行，最新在前

- 可按「工具 / 思考」筛选
- 可按轮次跳转（T1、T2…）
- 可搜索结论正文、工具名或 spill 路径
- 点开某条，会按需加载完整原文（不展开就不会重新付钱）

### 设置面板

| 配置项 | 默认值 | 什么时候改 |
|---|---|---|
| 启用折叠 | 开 | 临时关掉看对比 |
| 试运行 | 关 | **调整阈值前强烈建议先开**，只看效果不改会话 |
| 工具结果最小长度 | 1000 | 想折得更激进就调小，但不要低于 300 |
| 批量最小长度 | 8000 | 调小会更频繁触发折叠 |
| 保留最近步数 | 6 | 调大更保守，最近的步骤不动 |
| 超过多少步算陈旧 | 12 | 长回合内多久算「用完了」 |
| 分批跨度 | 20 | 超长回合拆批处理 |
| 折叠思考过程 | 开 | 折叠历史工具调用轮的 thinking |
| 折叠纯文本轮思考 | 关 | 只有路由会重发时才需要开 |

## 什么时候有用，什么时候没用

折叠不是无脑省 token，它的经济账取决于两件事。

**有用**：单条工具输出很大（读大文件、跑长日志、抓大量搜索结果），且后面还有很多步要用到同一上下文。这时折叠掉的正文会在后续每一步都省一次。

**没用甚至亏本**：会话很短，或者折叠发生时已经接近尾声。折叠会**打掉前缀缓存**——被你遮蔽处之后的所有内容要按全价重算一遍。如果省下的钱还不够这一次重算，净收益就是负的。

> 判断方法：打开标签页看「净收益」。负数说明这次折叠亏了，可以考虑调大「批量最小长度」，让折叠只在真正大块的内容上发生。

### 关于思考折叠

DeepSeek 官方路由（`dsh-llm-deepseek`）**不会重发纯文本轮的思考内容**，所以折它没有任何意义——插件默认就跳过这类轮次。「折叠纯文本轮思考」这个开关只有在你用会重发思考的路由（例如 `dsh-router-core`）时才需要打开。

另外，思考块有最小长度门槛（900 字符，约合折叠后固定输出的 328 字符）。太短的块折了不划算，插件会跳过。

## 面板上的数字怎么理解

**这些是估算，不是账单。**

插件会明确标注两种情况：

- **按真实用量计价** —— 会话上报了服务商 usage，数字锚定在真实计费上
- **仅为启发式估算** —— 会话没上报 usage，面板会提醒你这些只是 token 计数

「若从未折叠」那一列是**反事实**：不折叠的情况从未真实发生过，它是基于「步数不变、缓存行为不变」推断的。方向可信，具体数值不宜当账单看。

面板下方有个「估算前提」可以展开，列出所有依赖的假设。

## 常见问题

**折叠了但没看到标签页？**
检查插件是否启用、是否重启过。标签页在对话视图里，不在设置里。

**面板显示「净亏」？**
说明折叠发生得太晚，失效成本超过了收益。这是真实结论，不是错误。调大「批量最小长度」可以让折叠更保守。

**设置改了没生效？**
配置写入 profile 后需要重启。想先验证效果，用「试运行」模式。

**原文还能找回吗？**
能。每条折叠记录都带 spill 路径，在面板里展开即可读取。如果某条显示「不可恢复」，说明原文只存在于会话日志中且没有工具能取出——这种情况面板会直接标出来。

**折叠会影响模型判断吗？**
会以你看到的方式影响：模型看到的是「结论 + 原文路径」，而不是全文。所以插件折叠的是**已经得出结论的内容**，结论本身始终保留。

---

## 它不做什么

- **不调用模型**。所有决策都是会话日志加配置的纯函数，同样的输入永远得到同样的输出。
- **不改历史**。折叠记录是独立的事件，原始日志保持不变。
- **不猜**。阈值、收益、失效成本都是显式计算的，面板如实展示，包括负收益。
